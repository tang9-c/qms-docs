# 失效分析

失效分析是 FMEA 分析的第四步，目标是识别每个功能的潜在失效。本指南将介绍如何进行失效分析。

## 失效模式识别

- **目标**：识别每个功能的潜在失效。为每个功能项添加潜在的失效模式，并评估其严重度（S）、发生度（O）和探测度（D）。
- **角色**：实施中角色成员
- **操作**：
  - 系统会根据 "功能-失效"逻辑链 自动提示常见的失效模式、失效影响和失效原因。
  - 失效链：失效原因 -> 失效模式 -> 失效影响（局部/最终）。
  - 提示：利用 "基础数据库" 中的历史失效数据，避免遗漏。

## 关联失效

关联失效以功能网为基础，系统地推演每个功能如何失效，以及失效网的传播网络的一个反向分析模型。选择失效模式时，可继续关联失效。

## 重要流程控制

所有角色为【实施中】的项目成员都必须点击【完成分析】按钮。仅有当所有实施中成员都完成后，项目才会流转到风险分析阶段。此限制是为了避免形成太多的系统无效数据。
